# Windows port plan

Research: 2026-11-04. Baseline: `origin/main` at `3d7674e`. Documentation-only audit; no builds, labs, Windows sessions or performance measurements. “Implemented” below means reachable source, not a successful Windows test. November claims mean sources available on this date, not promises about later November releases.

## Recommendation

Keep Swift/AppKit on Mac, GTK on Linux, and shared Rust engine code. On Windows use **Rust + windows-rs, Win32 HWNDs, Direct2D/DirectWrite and DirectComposition for the pill/ink; native Win32 controls for Settings and History**. Target supported Windows 11 x64 and ARM64. Keep dictation free of browser runtimes. Preserve the Mac's 300×48 logical-pixel pill, exact states, coral palette and timing from [UI design](ui-design.md); 48 physical pixels at every DPI would make it too small on scaled screens.

The strongest counter-case is accessibility and polish: hand-drawing Settings would recreate a toolkit badly. Use actual common controls, keyboard navigation and UI Automation providers for custom pill actions; inspect with Narrator before committing to this stack. If that gate fails, default fallback is a thin **C# WinUI 3 Settings/History host over the same Rust engine**, with the Rust HWND pill unchanged. Do not rewrite the engine or Mac.

| Candidate | Decision | Reason / cost |
|---|---|---|
| Win32 + D2D/DirectWrite/Composition, Rust | Default | Fits existing windows.rs; precise nonactivation, mixed DPI and hit testing; no new runtime. Modern controls, high contrast and accessibility require deliberate work. |
| WinUI 3 / Windows App SDK | Fallback for ordinary windows | Microsoft recommends WinUI for new native UI; first-party authoring is C# / C++. Rust API access is not equivalent to a supported Rust XAML designer/toolchain. Adds SDK deployment and interop work. |
| Slint / egui / Iced | Do not select without a Windows accessibility bake-off | No browser, potentially shared views, but extra toolkit, native behavior and custom overlay work remain. Their current accessibility/parity was not verified here. |
| Tauri / Electron | Reject for dictation | Browser runtime conflicts with the explicit requirement; existing GTK views do not become Windows views. |

Sources: [WinUI guidance](https://learn.microsoft.com/en-us/windows/apps/winui), [supported language projections](https://learn.microsoft.com/is-is/windows/apps/develop/platform/), [Windows App SDK](https://github.com/microsoft/WindowsAppSDK). Shipping comparison: [Wispr Flow supports Windows x64 but explicitly excludes ARM](https://docs.wisprflow.ai/articles/1036674442-supported-devices-and-system-requirements); that establishes a real Windows dictation market, not proof of its internal stack or Koett parity.

## Windows boundaries and APIs

| Feature | Default implementation and test boundary |
|---|---|
| Global shortcut | `RegisterHotKey` with `MOD_NOREPEAT`; expose conflicts and reserved combinations. It registers chords, not a bare modifier release/hold. Keep configurable toggle and hold modes. |
| Bare Shift drawing | During recording only, Raw Input (`RegisterRawInputDevices`, `RIDEV_INPUTSINK`) to a hidden HWND, filtering immediately to modifier state and “another key held” booleans. Never collect characters, retain key histories, suppress typing or use `RIDEV_NOLEGACY`. A global modifier gesture necessarily observes keyboard state: cannot honestly promise zero keyboard observation. Ignore injected events where identifiable; require a release before arming, disarm on chords, use movement threshold and repeat the Mac gesture fixtures. Raw Input foreground/background behavior and rapid chords need a real desktop test. A minimal `WH_KEYBOARD_LL` observer returning `CallNextHookEx` is fallback only: timeout can silently remove it. |
| Pill | Topmost tool HWND, `WS_EX_NOACTIVATE`, `SWP_NOACTIVATE`, `WM_MOUSEACTIVATE → MA_NOACTIVATE`. Composition opacity/translation, actual RMS, reduced-motion setting; no synthetic waveform. Mouse-only hover actions must work without stealing keyboard focus. Provide keyboard alternatives through shortcuts/tray. |
| Ink / mixed DPI | One transparent topmost HWND per display; PMv2 manifest, `WM_DPICHANGED`, `EnumDisplayMonitors`, display-change handling. Store global physical coordinates and convert per-monitor DIPs; include negative coordinates, rotation and hotplug. Use documented layered-window pass-through when idle; accept pointer only while drawing. Do not assume `HTTRANSPARENT` alone passes input to unrelated processes. No overlay can both consume a pin and pass that same click to the underlying app. |
| Screenshot | `Windows.Graphics.Capture` interop `CreateForMonitor` / `CreateForWindow`, D3D11 frame pool, one bounded capture per explicit gesture. Exclude own HWNDs with `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` where supported; composite only the intended stroke/pin offscreen. Verify exclusion and HDR conversion; do not depend on sampling a visible ink frame. Protected content, secure desktop and capture-denying apps are not bypassable. Keep images in memory. |
| Paste and wrong-app guard | Capture target HWND + process identity at start; immediately before every chord compare foreground HWND/process, verify still alive and not Koett, reject changed focus or held modifiers. `SendInput` once, chosen Ctrl+V or Ctrl+Shift+V; no forced focus restoration. Recheck between image and text. Save exactly once even on failure; persistent Not pasted + Copy/Paste. Race between comparison and injection remains: Windows provides no atomic “paste only if this HWND is foreground” operation. An inserted-event count is not a receipt from the target. |
| Elevated app | UIPI blocks medium-integrity SendInput into elevated targets. Default: copy + visible recovery, never elevate the whole app. Optional signed, securely installed UIAccess helper is a separate security/deployment project, not a guaranteed bypass of UAC/secure desktop. Manual paste is the closest safe alternative. |
| PNG + HTML + text | One clipboard transaction: `CF_UNICODETEXT`, registered `PNG`, `CF_DIBV5`, registered `HTML Format` with UTF-8 byte offsets and escaped fragment. Standard bitmap fallback helps targets without PNG support. Keep identical payload for repeat paste. For apps needing image then text, retain explicit per-app chord and timed/observed-read fallback; no universal clipboard receipt exists. `GetClipboardSequenceNumber` + own marker: never overwrite a newer user copy while staging. Windows owns successful HGLOBAL data; release only on failure. |
| Microphone | Existing CPAL WASAPI backend; shared-mode event-driven capture, selected endpoint ID, device invalidation/change notifications, rate conversion and level preview. No disk, ASR, network or blocking channel sends on callback. Distinguish no samples from silence. Surface privacy Settings when disabled; test USB unplug, default-device switch and Bluetooth. |
| Pin context | UI Automation `ElementFromPoint`, process/window identity, `TextPattern.GetSelection`, URL via tested browser address-bar/document properties, hyperlink under pointer via element patterns. `IsPassword` before any text, selected text on by default, separately switchable and capped at 500 characters; timeout worker and reject stale results. UIA is provider-dependent: arbitrary apps need not expose URL, selection or YouTube position. Never use synthetic Ctrl+C to discover context. Browser extension + native messaging is the explicit fallback for URL/player time/private mode, not silent browser debugging access. |
| Login / tray | Existing HKCU Run key for unpackaged install, honor user-disabled startup; packaged build uses `StartupTask`. `Shell_NotifyIcon`, stable GUID, Explorer `TaskbarCreated` re-registration, full tray keyboard menu. One instance per user/session. |
| Pause media | `GlobalSystemMediaTransportControlsSessionManager`, inspect playback state and call `TryPauseAsync`, resume only the same session Koett paused. Never toggle Play/Pause blindly. Unsupported players need an explicit browser integration or no-op notice. |
| Ask / secrets | Share provider/SSE/TTS logic after removing Linux cfg boundaries; Windows Credential Manager or user-scoped DPAPI for keys. On-demand WGC image only. Optional WebView2 for Ask Markdown/math may load only when Ask opens; it must not start with dictation. Native renderer is an alternative if browser-free Ask becomes a requirement. |

Primary API evidence: [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey), [Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/using-raw-input), [hook limits](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc), [extended window styles](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles), [PMv2](https://learn.microsoft.com/en-us/windows/win32/hidpi/dpi-awareness-context), [capture sample](https://github.com/microsoft/Windows.UI.Composition-Win32-Samples/tree/master/cpp/ScreenCaptureforHWND), [capture exclusion](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity), [SendInput/UIPI](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-sendinput), [HTML format](https://github.com/MicrosoftDocs/win32/blob/docs/desktop-src/dataxchg/html-clipboard-format.md), [clipboard formats](https://learn.microsoft.com/en-us/windows/win32/dataxchg/standard-clipboard-formats), [WASAPI](https://learn.microsoft.com/en-us/windows/win32/coreaudio/wasapi), [UIA text](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingtextandtextrange), [UIA security](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview), [pause API](https://learn.microsoft.com/sv-se/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession.trypauseasync?view=winrt-20348).

## Speech, delivery and shared Rust

Keep the repo's pinned **sherpa-onnx 1.13.5**, ASR-only source build and ONNX Runtime CPU path first. Do not upgrade merely because [upstream now lists 2.0.x](https://github.com/k2-fsa/sherpa-onnx/releases). Ship a pinned runtime DLL set per architecture; clean-machine dependency checks are mandatory. CPU is the portable fallback for Intel/AMD and Qualcomm ARM64. Match current Linux model choice initially; adding options does not authorize changing Mac's default.

GPU is optional after measured CPU latency, accuracy, battery and memory gates. [ORT now recommends WinML for Windows](https://onnxruntime.ai/docs/get-started/with-windows.html); [DirectML is sustained engineering](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html). Do not choose DirectML as a new strategic dependency. Investigate WinML provider selection behind the engine boundary; compatibility with pinned sherpa, quantized Parakeet ops and Rust bindings is **unverified**. NVIDIA CUDA EP is a separate optional artifact with driver/CUDA compatibility costs. Qualcomm QNN/NPU needs a compatible ARM64 graph/provider/runtime; neither ARM64 compilation nor a Copilot+ label proves the model runs on the NPU. Always retain CPU; no GPU or NPU performance claim is verified here.

Use existing manifests, checksums, bounded extraction and atomic download promotion; explicit model sizes, progress, cancel/retry, resume only with validated range metadata, no partial model activation. Models downloaded once to user data, loaded once, licenses included, offline dictation thereafter. Windows ARM64 needs native MSVC Rust + native sherpa/ORT and codec dependencies, not just x64 emulation.

Dictionary: share Rust plain + biased transducer decoding, exact-term adoption and correction/replacement fixtures. [Upstream hotwords](https://k2-fsa.github.io/sherpa/onnx/hotwords/) do not establish CTC support. Repo `transcription/hotwords.rs::Bias::new` explicitly skips `model.int8.onnx` (110M CTC); Nemotron gets spelling only. Close this on **all** platforms with a benchmarked CTC rescorer/lexicon decoder or optional transducer sidecar, bounded by deadline and raw fallback; never relabel spelling replacement as acoustic hotwords. Align Linux/Windows spelling before and after S1-mini with Mac.

Share: audio buffers/resampling, model manifest/downloader, transcription/recovery, dictionary/corrections/replacements, history/schema/search, annotation/word alignment, pin sanitization, contact-sheet data and settings validation. Factor Linux-only media/assistant business logic into shared modules; retain native device, shortcut, clipboard, capture, secret, tray and window adapters. Do not move GTK into shared modules. Preserve Linux `clipboard_owner.rs`'s multi-format payload, bounded writers, ownership-race detection and “newer copy wins”; port the **contract**, not Wayland protocol objects. Keep Swift/Rust parity fixtures instead of replacing Swift with Rust.

## Distribution

Default: **signed per-user installer first**, with a stable install path, repair/uninstall and rollback; choose a maintained installer tool after validating its current release (not selected/pinned in this research). MSI/WiX is appropriate when enterprise deployment is required; do not invent a custom installer. Add MSIX + `.appinstaller` once capture/shortcuts/startup and update behavior pass under package identity. MSIX supplies [managed updates](https://learn.microsoft.com/en-gb/windows/msix/app-installer/auto-update-and-repair--overview); MSI/EXE needs a separate signed update feed. No silent replacement while recording/processing; verify publisher, signature and hash, retain last version, preserve user data. Store distribution can be another channel, not an assumption that sandboxing removes desktop requirements.

Azure **Artifact Signing** (formerly Trusted Signing) default for direct downloads: advertised Basic **US$9.99/month / 5,000 signatures**, tax/FX/extra usage excluded ([pricing](https://azure.microsoft.com/en-us/products/trusted-signing)). [Public Trust organization eligibility includes the EU](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart), so a Swedish company is geographically eligible; identity approval for Dyberg & Co AB is **not verified**. Swedish individuals are not covered by the documented US/Canada individual route. Timestamp EXE/DLL/installer signatures and use least-privilege CI identity. Traditional OV/EV certificate is fallback; vendor cost, token/cloud-signing terms and actual approval require quotes, not a guessed annual number.

[Microsoft's signing comparison](https://learn.microsoft.com/da-dk/windows/apps/package-and-deploy/code-signing-options) says signing does **not** guarantee instant SmartScreen reputation. Test a fresh download on a clean Windows profile and record the actual warning. EV is not a promise of no warnings. Build x64 and ARM64 packages separately; verify installer architecture selection, signature, upgrade/downgrade behavior and complete dependency closure on each. No release is authorized by this document.

## Real Windows without a Windows PC

| Route | What it can prove | What it cannot prove |
|---|---|---|
| Default: one local KVM Windows 11 guest | Genuine Windows desktop: installer, UIA/Narrator, tray, focus guards, clipboard, virtual dual monitors/DPI, CPU ASR and recovery | Native Qualcomm/NVIDIA speed, physical mixed-DPI monitors, real USB/Bluetooth behavior, host driver quirks |
| Cloud Windows desktop VM | Same functional tests without consuming PC RAM; persistent interactive console, screenshots and input automation | Hardware mic/GPU/NPU behavior unless explicitly supplied; RDP redirects audio/clipboard and may alter capture/rendering |
| Hosted Windows CI | Native compilation, unit tests, artifact structure/signatures, CPU WAV recognition | Human-equivalent interactive desktop, normal tray/focus/DPI or physical microphone; “CI passed” is not desktop proof |
| Self-hosted CI in guest | Repeatable UIA + screenshot/input checks while a user desktop stays unlocked | Service/session-0 execution is not an interactive session; locked/RDP-disconnected behavior must be checked |
| Borrowed x64 and ARM64 hardware | Final microphone, display, sleep/resume, CPU and accelerator acceptance | Broad compatibility from one machine alone |

Proposed VM budget (not allocated): **one guest, 4 vCPU, 8 GiB RAM**, dynamically allocated disk under `~/.cache/koett-windows/`, no /tmp and no simultaneous build/lab load. If host available memory cannot leave that plus headroom, use cloud instead; do not start a VM now. Use libvirt/QEMU with UEFI/OVMF, TPM 2.0 and Windows 11-compatible Secure Boot setup; official Windows image and valid license. [Windows requirements](https://www.microsoft.com/en-us/windows/windows-11-specifications), [libvirt TPM configuration](https://libvirt.org/formatdomain.html#tpm-device), [VirtIO Windows drivers](https://github.com/virtio-win/virtio-win-pkg-scripts). Hardware virtualization, current free RAM, licensing entitlement, agent console integration and guest GPU acceleration were not inspected.

Agents should control the **guest** through its isolated console or an authenticated guest UIA/screenshot bridge, never the host pointer. Supply prerecorded WAV fixtures separately from a live mic test. Save image + foreground HWND/PID + clipboard-format evidence per step. Use UIA automation first and pixel coordinates only for ink. [Microsoft requires an interactive agent for desktop UI tests](https://learn.microsoft.com/en-us/azure/devops/pipelines/test/ui-testing-considerations?view=azure-devops). Check cloud desktop Windows licensing and VM price before purchase; no provider/cost is verified here. No public RDP; shut down paid compute after use.

## Milestones: every gate ends on real Windows

1. **Desktop foundation:** run current Windows build in an approved guest; replace mock pill, demonstrate no focus theft while typing, tray restart, startup off/on, light/dark, reduced motion, Narrator and 100/150/200% scaling. Test Settings/History native controls here; use WinUI fallback only if accessibility/polish gate fails.
2. **Reliable dictation:** shared CPU engine, selected mic + preview, toggle/hold, silence, pause/resume/cancel, hotkey conflicts; paste exactly once into Notepad, browser editor and terminal. Switch foreground during ASR, try elevated editor, unplug mic, fail history writes. Verify persistent Copy/Paste rescue, failed audio only on ASR failure, and no storage blocking delivery. Run 30-minute live capture before claiming long-session support.
3. **Words and records:** native searchable history, export, dictionary import/export, Fix a word and explicit suggestion acceptance, replacements, optional formatting with raw fallback. Run the same speech/near-miss corpus and Swift/Rust fixtures; compare outputs and timings. Add model switching/v3/110M/Nemotron without changing defaults. CTC acoustic dictionary gap stays open until its own corpus passes.
4. **Draw and pin:** exact Mac gestures, multimonitor mixed DPI/rotation/hotplug, undo, screen exclusion, timestamps/contact sheet, image+HTML+text repeat paste and newer-copy race. Test UIA URL/selection/password/private mode/YouTube across Edge, Chrome, Firefox, native editor and terminal; missing context must remain visibly absent, never guessed. Test cross-process click-through and typing capitals/chords during recording.
5. **Media and automation:** share URL/file transcription + CLI, browser focus selection and explicit pause/resume media. Prove offline dictation still works with no keys, network or browser runtime dependency. Give native actions documented CLI commands where practical. Ask was subsequently shelved on main; provider/key controls, one-image Ask, interruption, spoken reply and Markdown/math are outside the current product and must not be restored by this port. See [Windows media](windows-media.md) for the implementation and its limits.
6. **Distribution and parity release gate:** clean-install/upgrade/uninstall signed x64 and ARM64 artifacts, SmartScreen record, offline restart and rollback. Execute every [parity row](feature-parity.md) on Windows and close Mac/Linux gaps in parallel. Require physical x64 + Qualcomm ARM64 mic/display/sleep tests before advertising those architectures. No “all platforms” claim while a row is partial or untested.

No calendar estimate is justified before milestones 1–2. The earlier 4–7 human weeks is not a measured schedule; re-estimate from integration failures and acceptance throughput, separately from signing/hardware lead time.
